Appraisal: Status Transition

When an Ascription requests a lifecycle state transition (e.g., Draft → Active), the Definition Manager API runs an appraisal — a rule-checking pass that evaluates all applicable Starlark rules and CEL norms to determine if the transition is permissible. This workflow shows the full appraisal cycle.

⚙ Definition Manager API (automated)
Ascription Lifecycle:
Draft → Proposed → Active → Suspended → Retired
1

Request Transition

User or Review Board requests a state change on an Ascription. The request is submitted via the Definition Manager API or the UI.

2

Appraisal Engine: Collect Applicable Rules

The Definition Manager identifies all rules that apply to this transition: Starlark lifecycle rules, CEL norm assertions, and archetype-specific constraints from each layer.

⚙ API: POST /api/v1/ascriptions/{id}/appraise
┌──────────────────────────────────────────────┐ │ Appraisal Context │ ├──────────────────────────────────────────────┤ │ Transition: Draft → Active │ │ Subject: API Gateway │ │ │ │ Applicable Rules: │ │ [1] lifecycle.starlark — Draft→Active guard │ │ [2] togaf_arch_principle_compliance.cel │ │ [3] nis2_encryption_at_rest.cel │ │ [4] iso25010_security_confidentiality.cel │ │ [5] nis2_access_control_mfa.cel │ │ [6] gdpr_data_minimization.cel (if PII) │ │ │ │ Total: 6 rules to evaluate │ └──────────────────────────────────────────────┘
3

Appraisal Engine: Evaluate Rules

Each rule is evaluated against the subject's current state and properties. Results are categorized as PASS, WARN, or BLOCK.

⚙ Starlark Rule API + CEL Evaluator
✅ PASS — lifecycle.starlark: Draft→Active transition allowed (all prerequisite fields populated)
✅ PASS — togaf_arch_principle_compliance.cel: API Gateway conforms to 3/3 applicable architecture principles
✕ BLOCK — nis2_encryption_at_rest.cel: subject.properties.encryption_at_rest is false. Required: true (NIS2 Art.21 §2(d))
✅ PASS — iso25010_security_confidentiality.cel: Confidentiality measures verified
⚠ WARN — nis2_access_control_mfa.cel: MFA configured but fallback to single-factor exists. Tolerance: advisory (non-blocking)
✅ PASS — gdpr_data_minimization.cel: Not applicable (subject does not hold PII)
4

Appraisal Verdict

The appraisal aggregates findings into a final verdict. Any BLOCK finding prevents the transition. WARN findings are reported but non-blocking (unless the norm has strict tolerance).

Appraisal Decision:
✅ CLEAR
All rules pass (or only advisory warnings). Transition proceeds automatically. Ascription moves to requested state. Activity log records the transition.
✕ BLOCKED
One or more BLOCK findings. Transition is denied. Findings are attached to the Ascription. Owner must remediate and re-request, or escalate to Review Board.
┌──────────────────────────────────────────┐ │ Appraisal Result: BLOCKED │ ├──────────────────────────────────────────┤ │ Rules evaluated: 6 │ │ Passed: 4 │ │ Warnings: 1 (advisory) │ │ Blocked: 1 │ │ │ │ Blocking finding: │ │ nis2_encryption_at_rest.cel │ │ "encryption_at_rest must be true" │ │ │ │ Verdict: TRANSITION DENIED │ └──────────────────────────────────────────┘
5

Remediate & Re-Request

The owner reviews blocking findings, updates the subject's properties or configuration, and re-submits the transition request. The appraisal runs again.

📋 Screen: 07-ascriptions-view.html (detail panel)
┌──────────────────────────────────────────────┐ │ Remediation on ASC-2024-271 │ ├──────────────────────────────────────────────┤ │ Finding: nis2_encryption_at_rest.cel BLOCK │ │ │ │ Action: Set encryption_at_rest = true │ │ Updated by: Infra Team (2026-01-15) │ │ │ │ [Re-submit Transition Request] │ │ │ │ — OR — │ │ │ │ [Escalate to Review Board] │ │ (board can override with documented waiver) │ └──────────────────────────────────────────────┘
6

Transition Complete

After remediation, the re-appraisal passes. The Ascription transitions to the requested state. Event is published to the event bus and recorded in the activity log.
